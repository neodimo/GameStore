# GameStore context

## Product premise

GameStore is a Windows and Linux retro-game discovery catalog inspired by the breadth of CDRomance-style platform browsing. It emphasizes official regional box artwork, English playability, unusually strong filtering, editorial similarity shelves, transparent source provenance, and in-place game details.

## Media plan

- Layered artwork/screenshot candidates from retro metadata providers, with exact release/revision scope preferred over region, platform, or game-level media.
- Candidate artwork is classified (front scan, full cover, reconstruction, 3D render) and never silently replaces a curated choice.
- Expanded details prioritize a large scrollable screenshot gallery beside a substantial 4:3 short-loop video pane; metadata, acquisition, transfer, and source links live in the right rail.
- Media records retain scope, region, provider ID, source, dimensions/duration, attribution, freshness, confidence, and override history.

## Distribution and storage invariant

- Keep the repository and installers media-light: ship executable code, UI assets, schemas, provider adapters, and compact textual/catalog metadata.
- Do not commit or package per-game covers, screenshots, video files, or bulk media archives. Users obtain those after installation through built-in auto-scrapers/providers.
- Downloads require an explicit user action or an enabled in-app cache policy. Show provider attribution, progress, failures, retries, cache size, and clear-cache controls.
- Store fetched media in the platform application-data/cache directory. Cache clearing must not erase favorites, catalog corrections, artwork override history, or provenance.
- Never bundle video. Resolve it from attributed providers: exact-release EmuMovies video snaps cache locally after user sign-in; otherwise a strictly matched Internet Archive longplay streams only the short looping range. Bundled media is limited to small app-owned assets such as the icon, logo, loading UI, and missing-media placeholders.
- CI should guard this invariant with repository/release size budgets and a check that rejects newly bundled per-game media.
- The enforced budgets and UI-asset allowlist live in `config/media-light.json`; `scripts/check-media-light.mjs` checks the source tree, compiled bundles, and platform artifacts in release CI.

## Current implementation

Version 0.12 is an Electron + React/TypeScript desktop application with matching Windows and Linux functionality. Its desktop shell follows the approved mockup direction: fixed navigation rail, global search, platform/filter bars, dense art-led shelves, and anchored inline details. Its PS1 library starts with 1,462 English-language USA retail records imported reproducibly from pinned OpenVGDB v29.0 metadata; demos, magazine samplers, later discs, and duplicate revisions are collapsed. It then retains Europe-only English releases where no USA release is present and the existing explicitly documented English fan translations. OpenVGDB descriptions are carried only with their per-game reference URL; games without source copy explicitly show that it is unavailable. Unsourced editorial quotes are not displayed. Four of nine discovery shelf recipes and six qualifying games per shelf are shuffled once on each application launch. The app includes local favorites/export, filters, translation records, media/video states, managed downloads, a persistent MiSTer cart, and stateful outbound sources. GitHub Actions builds a Windows NSIS installer plus Linux AppImage and Debian packages.

Primary browsing intent is explicit: curator shelves appear only in unfiltered Discover, search/filter results start immediately below the controls, and Favorites is a real favorites-only view with its own active and empty states. Nonfunctional future-platform navigation is visibly disabled until that catalog exists.

Box art resolves by fuzzy-matching the live Libretro thumbnail index rather than guessing one exact filename. The main process fetches and disk-caches the full No-Intro filename list per folder (7-day TTL, stale cache preferred over no artwork); the renderer scores it locally in `src/artMatch.ts`. Scoring blends word-level and character-level similarity over normalized titles, rewards the catalog region, and demotes demos, prototypes and later discs. Two floors apply: the automatic resolver keeps a strict 0.6 floor so it refuses rather than inventing a cover, while the manual deep-search panel browses at 0.3 because the user is choosing by eye. Right-clicking any game opens details, alternate-artwork search across box art/title screen/screenshot/TheGamesDB, or a reset to the automatic match; overrides persist locally with their source label. Measured against the live 9,339-file index, the 30-game slice resolves 30/30 with no incorrect picks, against 13/30 for the previous seeded-filename path.

Libretro Thumbnails is the zero-configuration art source. Users can store a TheGamesDB API key locally from Settings and explicitly apply searched front-cover candidates from a game's expanded details. Cover containers derive their ratio from the loaded scan and use `object-fit: contain`, so the UI preserves official package/scan proportions rather than cropping every system into one poster shape. TheGamesDB secrets stay in Electron's main process and use OS-backed safe storage where available.

Commercial game files are never bundled. The private provider boundary accepts user-selected supported host links and Real-Debrid magnets, resolves them with locally encrypted account tokens, and refuses executables/unrelated files. Downloads finalize through `Documents/GameStore/.incoming` and a safe ZIP staging boundary into the console-aware managed library: disc/multi-file releases use `Games/<console>/<title>/`, while single-file cartridge images use `Games/<console>/`; source filenames are preserved. A ZIP is removed only after successful extraction and installation. TorBox host-link resolution is implemented; TorBox magnet file selection remains explicitly unsupported until verified. RetroGameTalk remains a visible source-page fallback rather than a scraped ROM index.

Debrid credentials alone cannot discover torrents. Users may configure a trusted external collection `.torrent` URL once per platform. GameStore fetches metadata only, parses the contained file manifest locally, fuzzy-matches title and region, and exposes exact candidates. Real-Debrid collection downloads upload the torrent and select only matching file IDs before resolving links. During the provider-side queue/cache stage, acquisition reports an explicit preparation state and elapsed wait rather than presenting a frozen `0%` transfer; byte progress begins only when the provider returns a direct file. No collection URL, torrent manifest, or commercial-ROM index ships in the repository/installers. TorBox's official cached-file/per-file route is the next authenticated integration gate.

RetroGameTalk repository search is retained as an explicit, unverified source-page fallback per game. **Scan network** performs a user-started, rate-limited SSH/SFTP probe of local IPv4 `/24` networks, labels likely hostname matches, and exposes unknown SSH candidates for explicit selection. Credential testing checks `/media/fat` before confirming MiSTer/SuperStation layout. Completed downloads enter the disk-backed MiSTer cart in `Documents/GameStore/library.json`; header checkout transfers the entire queue from its managed paths with byte progress, removes each successful item from the cart, and retains local library files. PS1 CHD or complete BIN/CUE sets transfer to `/media/fat/games/PSX/<game>` with per-game grouping. Hardware-specific connection/write validation remains a user-side acceptance step.

GameStore maintains a compact, install-local cache of the configured device's immediate `/PSX` game-folder names. The first catalog session after configuring a device begins one background SFTP listing; cards never wait on it or make individual device requests. Exact normalized title matches get a green drive badge meaning the game is already present on the connected MiSTer/SuperStation. **Refresh device library** in Settings deliberately rescans. The feature is inventory-only: it never deletes, overwrites, or otherwise manages remote files.

The header includes an in-app release updater. Windows NSIS and Linux AppImage builds check the public GitHub Releases feed, download and stage updates in the background with progress, then require an explicit **Restart to update** action. `.deb` installations report that updates belong to the system package manager. Release jobs must attach `latest.yml` / `latest-linux.yml` plus blockmaps so installed clients can resolve differential updates.

Expanded details place a larger cover, description, and facts in a left rail, while the right media column carries acquisition, a looping preview, and large primary-release gameplay screenshots. Navigation-only sticky/z-index rules are scoped to the shell’s direct sidebar, so the nested cover/details rail remains in document flow below global search. Libretro `Named_Snaps` and `Named_Titles` resolve through the same strict title/release matcher as artwork; galleries use one exact retail printing, exclude demo/beta/prototype media, and contain at most one title screen with Disc 1 preferred. Preview-captured frames augment the gallery only when they come from an exact, region-matched EmuMovies snap—never from an Archive longplay whose uploader title does not prove region. Users sign into EmuMovies directly in Settings with their forum username/password on `files.emumovies.com:21`; the username and encrypted password remain install-local, the FTP index is cached, and exact filename matches supply compact video snaps. The connection tries TLS, then Plain FTP only when TLS itself cannot connect. Content discovery understands both system-first and quality-first Official FTP trees while excluding later Sony systems. An FTP rejection is reported as an authentication failure, never inferred to be a membership downgrade. When EmuMovies is unavailable, a strict Internet Archive match streams a short byte range from a longplay rather than downloading it. Settings reports cache bytes/path and provides a clear action that does not erase user curation.

Media discovery is demand-led: browsing never launches a catalog-wide media crawl. Opening a title resolves its exact-release screenshots and preview while sharing the provider indexes and the same in-flight promise for repeated opens. Screenshot caching begins in parallel with video-provider resolution, so a slow or unavailable provider cannot stall the gallery. Clearing the disposable cache resets the shared indexes without erasing user curation.

## Acceptance direction

The original 30 adversarial fixtures remain the hand-verified data-quality core inside the 100-game catalog. Expanded titles have explicit lightweight Libretro cover fallbacks and participate in runtime fuzzy media matching; broader exact-release coverage remains an ongoing data-quality gate.

## Release workflow

For GameStore, wrapping up an approved change means carrying it through the complete release path by default: merge the green PR, tag the version, wait for Windows and Linux release jobs, and verify the published installers plus updater metadata. Stop at a draft/release candidate only when Omid explicitly asks for review before release or a real acceptance gate prevents safe publication.
