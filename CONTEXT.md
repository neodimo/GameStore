# GameStore context

## Product premise

GameStore is a Windows and Linux retro-game discovery catalog inspired by the breadth of CDRomance-style platform browsing. It emphasizes official regional box artwork, English playability, unusually strong filtering, editorial similarity shelves, transparent source provenance, and in-place game details.

## Media plan

- Layered artwork/screenshot candidates from retro metadata providers, with exact release/revision scope preferred over region, platform, or game-level media.
- Candidate artwork is classified (front scan, full cover, reconstruction, 3D render) and never silently replaces a curated choice.
- Expanded details prioritize a large scrollable screenshot gallery beside a substantial 4:3 short-loop video pane; metadata, acquisition, transfer, and source links live in the right rail.
- Media records retain scope, region, provider ID, source, dimensions/duration, attribution, freshness, confidence, and override history.

## Distribution and storage invariant

- Keep the repository and installers media-light: ship executable code, UI assets, schemas, provider adapters, and compact textual/catalog metadata.
- Do not commit or package per-game covers, screenshots, video files, or bulk media archives. Users obtain those after installation through built-in auto-scrapers/providers.
- Downloads require an explicit user action or an enabled in-app cache policy. Show provider attribution, progress, failures, retries, cache size, and clear-cache controls.
- Store fetched media in the platform application-data/cache directory. Cache clearing must not erase favorites, catalog corrections, artwork override history, or provenance.
- Never bundle video. Resolve it from attributed providers: exact-release EmuMovies video snaps cache locally after user sign-in; otherwise a strictly matched Internet Archive longplay streams only the short looping range. Bundled media is limited to small app-owned assets such as the icon, logo, loading UI, and missing-media placeholders.
- CI should guard this invariant with repository/release size budgets and a check that rejects newly bundled per-game media.
- The enforced budgets and UI-asset allowlist live in `config/media-light.json`; `scripts/check-media-light.mjs` checks the source tree, compiled bundles, and platform artifacts in release CI.

## Current implementation

Version 0.16 is an Electron + React/TypeScript desktop application with matching Windows and Linux functionality. Its desktop shell follows the approved mockup direction: fixed navigation rail, global search, platform/filter bars, dense art-led shelves, and anchored inline details. Its PS1 library starts with 1,379 English-language USA retail records imported reproducibly by `scripts/import-ps1-catalog.py`; demos, magazine samplers, cheat discs, bonus albums, later discs, and duplicate revisions are excluded or collapsed. It then retains Europe-only English releases where no USA release is present and the existing explicitly documented English fan translations. Unsourced editorial quotes are not displayed. Four of nine discovery shelf recipes and six qualifying games per shelf are shuffled once on each application launch. The app includes local favorites/export, filters, translation records, media/video states, managed downloads, a persistent MiSTer cart, and stateful outbound sources. GitHub Actions builds a Windows NSIS installer plus Linux AppImage and Debian packages.

## Catalog metadata sources

Two pinned providers feed the import and neither dump is committed. Pinned OpenVGDB v29.0 decides which releases exist and what No-Intro/Redump filename each is published under, because it is keyed on real ROM dumps. It is a weak source for human-facing fields: of its 1,695 USA English PlayStation release rows only 244 carry a release date or developer and only 658 carry a genre or description, and merging the regional rows for the same title recovers essentially none of that gap. The LaunchBox Games Database covers the same library at 93-95% on those fields and adds max players, publisher, ESRB and a community rating, so it is layered on top. 1,374 of 1,379 records resolve by exact normalized-title lookup against LaunchBox's own names plus its alternate names, which is why the import needs no fuzzy scoring at all.

Precedence is per field. OpenVGDB written descriptions win because they arrive with a verifiable reference URL, except for the 173 that are a generated sentence restating fields the catalog already displays; those lose to a real LaunchBox overview. LaunchBox leads on genre because its 27-term controlled vocabulary keeps the filter dropdown coherent where OpenVGDB emits free text such as `Driving, Racing, Snow / Water`. Both providers fold into one alias-mapped vocabulary, so the genre filter cannot grow near-duplicate entries. A community score standing on fewer than five votes is discarded. Every description still carries a per-game reference URL, and games with no source copy explicitly show that it is unavailable.

The resulting catalog carries a year for 1,373 records, genres for 1,375, copy for 1,371, a developer for 1,373 and a player count for 1,359 out of 1,379 — better than 99% on every field the card and detail view render, against 202/586/586/202/0 out of 1,462 before. Card subtitles and detail headers join only the fields that exist, so a record the providers know nothing about reads as blank rather than rendering a release year of `0`. Coverage floors in `src/catalog.test.ts` sit under the measured numbers and fail the build if a future import silently reverts to a thin source.

**Discs that are not a game to play are excluded at import.** Redump lists them because they are real PlayStation discs; a catalog for finding something to play should not, and one of them had been surfacing inside a curator shelf. The importer drops 124 provider rows in four labelled categories: 8 cheat devices (GameShark, Code Breaker, PS-X-Change), 109 demo/sampler/magazine cover discs collapsing to 69 titles (the Official U.S. PlayStation Magazine run, retailer and publisher demo CDs, the Squaresoft Collector's CDs, the Final Fantasy VII Interactive Sampler), 2 bonus discs whose own games remain — the Gran Turismo 2 album and the Persona 2 bonus disc — and 4 promo discs named individually.

Those last four exist because pattern matching has a tail. `Pizza Hut Disc 1` and `2`, `PlayStation Picks` and `Toys 'R' Us: Attack of the Killer Demos!` share no naming pattern with each other or with anything above; their own provider copy is what identifies them ("a special Demo / Promotion Give-away", "a sampler disc full of game demos and trailers that was shipped with every PlayStation at launch"). Widening a regex until it caught them would start eating real games, so `NON_GAME_TITLES` names them. LaunchBox's `ReleaseType` field is not a usable signal here — it reads `Released` for all four.

`Ridge Racer Bonus Turbo Mode Disc` is deliberately kept. It is a bonus disc, but a playable game rather than a demo reel or an album, which is the line drawn here.

Every pattern is anchored or requires an adjacent word, because the obvious keyword version of this filter deletes real games: `underground` takes out Medal of Honor: Underground and Professional Underground League of Pain, `trial` matches inside "Extra-Terrestrial", and `xplorer` matches Barbie: Explorer and Dora the Explorer. Removing 79 discs is worth nothing if it also removes one game somebody wanted, so those near misses are pinned by name in a test alongside the exclusion assertions. Educational titles are deliberately still in: they were not part of the approved exclusion and are arguably playable software.

## Translation-management contract

- Integrated patching must preserve the verified source ROM/disc image unchanged and write a separate translated copy.
- Local metadata may identify that copy as translated, but MiSTer/SuperStation export must retain the catalog's canonical original release naming convention so its normal artwork scraper finds the existing box art without user renaming or custom artwork.
- Patch installation must verify the expected source revision/checksum before applying patch data; a mismatch must stop safely rather than producing a questionable image.

**Discovery is manual by necessity; everything after the download click is automatic.** ROMhacking.net closed and now returns HTTP 403, and its patch database was preserved on the Internet Archive. The active community moved to romhack.ing and Romhack Plaza, neither of which offers an API, and romhack.ing's `robots.txt` is `Disallow: /`. The one machine-readable mirror of the old database (`zach-morris/romhack_db`, generated from archive.org WARCs) covers cartridge systems only and holds no PlayStation patches. GameStore therefore opens the curated patch page in an isolated in-app browser. The user navigates and clicks download once; before page navigation GameStore prepares `Documents/GameStore/Patches/<title>/`, then assigns Electron's managed save path synchronously inside `will-download` so Chromium never opens a Save As dialog. ZIP archives are safely extracted, the manifest-named patch is selected, the browser closes, and that file returns directly to the translation panel. A page cannot access GameStore or the user's normal browser session.

**`electron/patchFormats.ts`** applies IPS, UPS, BPS and PPF (encodings 1.0, 2.0 and 3.0) as pure buffer-to-buffer decoders with no native dependency, so PlayStation patching no longer needs a 2003-era Windows GUI. What matters downstream is not the format but whether a patch can prove it belongs to the image being patched. BPS and UPS embed a CRC32 of their own source and target and reject a wrong image themselves. PPF2 and PPF3 may embed a 1 KiB sample of the original at offset `0x9320`, which is a real check but a weak one. PPF1 and IPS prove nothing at all, and PPF is what PlayStation translations overwhelmingly ship as.

**`src/translationManifest.ts`** is the hand-maintained curated list that closes that gap, and **`scripts/import-redump-targets.py`** resolves each record's named release against the Redump PlayStation DAT into a real size, CRC32 and SHA-1 in `src/redumpTargets.ts`. A release name and serial together are the key, because 403 PlayStation serials in the DAT cover more than one image — a revision keeps its predecessor's serial. Only referenced releases are emitted, since the full DAT is 13,591 entries. `targetVerified` is deliberately separate from having a serial: it claims someone confirmed which release a specific patch expects, and a test refuses that claim unless the patch's own hash is on file.

Building the manifest immediately exposed serials the catalog had hand-written and got wrong. `Tobal No. 2` claimed SLPS-01025, which Redump lists as *Dare Devil Derby 3D*; `Linda³ Again` claimed SCPS-45124, which Redump does not list at all; `Baroque` names the Genteiban limited edition where a standard SLPM-86759 also exists. Each catalog record's base release is now derived from the manifest rather than typed beside it, for the same reason the translation search term is derived from the title: it makes that drift impossible.

**`electron/translationManager.ts`** enforces the contract. A manifest SHA-1 is checked first because it is the stronger claim; failing that, a self-verifying container counts; failing both, patching is refused rather than producing an unproven image, and an explicit user override is recorded permanently in the provenance entry. The source is opened read-only and never written. The patched copy is written to a `.partial` file and renamed, lands in `Games/PSX/<title> (English)/`, and keeps the canonical original release filename so artwork and MiSTer export still resolve — the copy is marked translated by its folder and its record, never by its name. A cue sheet beside the source is copied with its FILE reference retargeted. Every application records the patch SHA-256, source size/CRC32/SHA-1, output size/SHA-1, container, and how verification was satisfied, in `Documents/GameStore/translations.json`.

The original image is resolved automatically from the matching PSX item already created by **Add to cart**. A single BIN/IMG/ISO needs no second file picker; ambiguous multi-disc items still refuse to guess and retain the manual escape hatch. xdelta/VCDIFF is decoded through a packaged cross-platform N-API implementation, with the same source-preservation and provenance rules as the other containers. The original fixed-heap WebAssembly wrapper was removed after the first real 399,701,232-byte image exposed that it could not hold source, patch, and output together and surfaced a bogus typed-array length. Native binaries are explicitly unpacked from ASAR and verified from the packaged Electron runtime. Mizzurna Falls is the first fully modelled xdelta record: its published source SHA-1 matches Redump and its published translated-output SHA-1 is checked before any file is written.

Still open: `.7z` patch archives are not unpacked; multi-disc sets need one record per disc, which `Kowloon's Gate` documents but does not do; and the whole image is held in memory while patching, which remains memory-heavy for a PlayStation disc.

Primary browsing intent is explicit: curator shelves appear only in unfiltered Discover, search/filter results start immediately below the controls, and Favorites is a real favorites-only view with its own active and empty states. Nonfunctional future-platform navigation is visibly disabled until that catalog exists.

Box art resolves against the live Libretro thumbnail index rather than guessing one exact filename. The main process fetches and disk-caches the full No-Intro filename list per folder (7-day TTL, stale cache preferred over no artwork); the renderer resolves it locally in `src/artMatch.ts`.

Resolution runs in two phases so a full catalog never blocks the interface. Imported records carry the No-Intro `coverName` they were published under, so the large majority of titles resolve by map lookup (1,259 of 1,486 when measured, before non-games were excluded); only the remainder are fuzzy-scored, in slices handed back to the event loop. Filename parsing, normalization and bigram construction are hoisted into a prepared index built once per fetched file list, because that work depends on the filename rather than on the title being searched for. Together these took a full-catalog resolve from 67.8s of synchronous main-thread work to roughly 1s of interruptible work at an identical 1,378/1,486 match count on that same catalog, and a 20-second instrumented launch records zero long tasks. A test asserts the seeded shortcut never disagrees with the fuzzy matcher it short-circuits, so speed cannot silently cost accuracy.

Scoring blends word-level and character-level similarity over normalized titles, rewards the catalog region, and demotes demos, prototypes and later discs. Two floors apply: the automatic resolver keeps a strict 0.6 floor so it refuses rather than inventing a cover, while the manual deep-search panel browses at 0.3 because the user is choosing by eye. Right-clicking any game opens details, alternate-artwork search across box art/title screen/screenshot/TheGamesDB, or a reset to the automatic match; overrides persist locally with their source label. Measured against the live 9,339-file index, the 30-game slice resolves 30/30 with no incorrect picks, against 13/30 for the previous seeded-filename path.

Libretro Thumbnails is the zero-configuration art source. Users can store a TheGamesDB API key locally from Settings and explicitly apply searched front-cover candidates from a game's expanded details. Cover containers derive their ratio from the loaded scan and use `object-fit: contain`, so the UI preserves official package/scan proportions rather than cropping every system into one poster shape.

Libretro publishes each cover as a 512x512 PNG averaging ~433 KB, which the grid paints into cards a fraction of that size. Grid covers are therefore downscaled to 384px on the long edge and re-encoded once on first sight, into the disposable media cache, and served locally afterwards — measured at ~40 KB per cover, roughly 91% smaller, with aspect ratio preserved. Caching is gated on approaching the viewport, so browsing pulls only the covers actually looked at instead of the whole library; a cache miss costs the one upstream fetch the renderer would have made anyway, and a cache failure falls back to the remote original so it can never cost a visible cover. The expanded detail view deliberately opts out and keeps the full-resolution original, since that is the one place the extra pixels are visible. Catalog cards additionally use `content-visibility`, so covers scrolled out of view release their decoded bitmaps rather than accumulating across a long scroll. TheGamesDB secrets stay in Electron's main process and use OS-backed safe storage where available.

Commercial game files are never bundled. The private provider boundary accepts user-selected supported host links and Real-Debrid magnets, resolves them with locally encrypted account tokens, and refuses executables/unrelated files. Downloads finalize through `Documents/GameStore/.incoming` and a safe ZIP staging boundary into the console-aware managed library: disc/multi-file releases use `Games/<console>/<title>/`, while single-file cartridge images use `Games/<console>/`; source filenames are preserved. A ZIP is removed only after successful extraction and installation. TorBox host-link resolution is implemented; TorBox magnet file selection remains explicitly unsupported until verified. RetroGameTalk remains a visible source-page fallback rather than a scraped ROM index.

Debrid credentials alone cannot discover torrents. Users may configure a trusted external collection `.torrent` URL once per platform. GameStore fetches metadata only, parses the contained file manifest locally, fuzzy-matches title and region, and exposes exact candidates. Real-Debrid collection downloads upload the torrent and select only matching file IDs before resolving links. During the provider-side queue/cache stage, acquisition reports an explicit preparation state and elapsed wait rather than presenting a frozen `0%` transfer; byte progress begins only when the provider returns a direct file. No collection URL, torrent manifest, or commercial-ROM index ships in the repository/installers. TorBox's official cached-file/per-file route is the next authenticated integration gate.

RetroGameTalk repository search is retained as an explicit, unverified source-page fallback per game.

**The device is identified by name and by key, never by address.** A stored IP is a DHCP lease, so every saved address goes stale at once when the router reshuffles, which is what made connecting feel unreliable. Settings now leads with a device name defaulting to `MiSTer.local` — a MiSTer runs avahi and answers to its own hostname — and the address field is a cache the app refreshes on its own. `electron/mdns.ts` resolves that name with a one-shot multicast query rather than the OS resolver, because only Windows and macOS answer `.local` natively and a Linux host needs `nss-mdns` wired in; the query sets the unicast-response bit and binds an ephemeral port so it never contends with a system avahi-daemon for port 5353.

When the saved address stops answering, `locateDevice` re-finds the device before reporting any failure: configured address, then every candidate name in one multicast round trip, then the sweep. **Reachability is not identity.** A home network usually has other machines on SSH, so a rediscovered candidate is adopted only when it presents the SHA-256 SSH host key recorded on the first successful connection — `hostVerifier` rejects a mismatch before authentication, so a wrong device never sees the password. With no key on file yet, the candidate must have `/media/fat`. A newly adopted address is saved, the cached PSX listing is invalidated, and the renderer is told the device moved.

Anything expensive is gated on a 450 ms TCP probe first, because a stale address otherwise sits in SSH's connect for over a minute and turns a moved device into an apparent hang. **Scan network** performs a user-started, rate-limited SSH/SFTP probe of local IPv4 `/24` networks seeded with mDNS hits, labels likely hostname matches, and exposes unknown SSH candidates for explicit selection. Its reverse-DNS labelling runs after the sweep, concurrently, on a 2-second budget: doing it inside the sweep loop cost 31 seconds for four hosts because an address with no PTR record waits out the resolver's full retry budget, and that single change took a scan from 58.5s to 7.7s and the whole locate-and-fail path from 103s to 13s. Credential testing checks `/media/fat` before confirming MiSTer/SuperStation layout and reports the address it reached. Completed downloads enter the disk-backed MiSTer cart in `Documents/GameStore/library.json`; header checkout transfers the entire queue from its managed paths with byte progress, removes each successful item from the cart, and retains local library files. PS1 CHD or complete BIN/CUE sets transfer to `/media/fat/games/PSX/<game>` with per-game grouping. Hardware-specific connection/write validation remains a user-side acceptance step.

GameStore maintains a compact, install-local cache of the configured device's immediate `/PSX` game-folder names. The first catalog session after configuring a device begins one background SFTP listing; cards never wait on it or make individual device requests. Exact normalized title matches get a green drive badge meaning the game is already present on the connected MiSTer/SuperStation. **Refresh device library** in Settings deliberately rescans. The feature is inventory-only: it never deletes, overwrites, or otherwise manages remote files.

The header includes an in-app release updater. Windows NSIS and Linux AppImage builds check the public GitHub Releases feed, download and stage updates in the background with progress, then require an explicit **Restart to update** action. `.deb` installations report that updates belong to the system package manager. Release jobs must attach `latest.yml` / `latest-linux.yml` plus blockmaps so installed clients can resolve differential updates.

Expanded details place a larger cover, description, and facts in a left rail, while the right media column carries acquisition, a looping preview, and large primary-release gameplay screenshots. Navigation-only sticky/z-index rules are scoped to the shell’s direct sidebar, so the nested cover/details rail remains in document flow below global search. Libretro `Named_Snaps` and `Named_Titles` resolve through the same strict title/release matcher as artwork; galleries use one exact retail printing, exclude demo/beta/prototype media, and contain at most one title screen with Disc 1 preferred. Preview-captured frames augment the gallery only when they come from an exact, region-matched EmuMovies snap—never from an Archive longplay whose uploader title does not prove region. Users sign into EmuMovies directly in Settings with their forum username/password on `files.emumovies.com:21`; the username and encrypted password remain install-local, the FTP index is cached, and exact filename matches supply compact video snaps. The connection tries TLS, then Plain FTP only when TLS itself cannot connect. Content discovery understands both system-first and quality-first Official FTP trees while excluding later Sony systems. An FTP rejection is reported as an authentication failure, never inferred to be a membership downgrade. When EmuMovies is unavailable, a strict Internet Archive match streams a short byte range from a longplay rather than downloading it. Settings reports cache bytes/path and provides a clear action that does not erase user curation.

Media discovery is demand-led: browsing never launches a catalog-wide media crawl. Opening a title resolves its exact-release screenshots and preview while sharing the provider indexes and the same in-flight promise for repeated opens. Screenshot caching begins in parallel with video-provider resolution, so a slow or unavailable provider cannot stall the gallery. Clearing the disposable cache resets the shared indexes without erasing user curation.

EmuMovies authentication and media discovery are separate operations. Sign-in validates and stores the credential without scanning media. Settings has a provider-independent **Scraping** section organized by media type, with a shared **skip titles already containing the desired media type** policy. Video's **Scrape** action opens a deliberate console picker; account controls never expose console/index actions. A targeted video scrape uses an intent-ranked path resolver: fuzzy console aliases plus video/snap and HD/HQ/SQ signals are scored ahead of generic provider folders and later-system siblings are excluded. Nearby quality tiers are merged per game because a high-quality tier may contain only a partial set: each title takes a safe HD match when available, otherwise HQ, otherwise SQ. Matching uses the catalog's canonical release name first and confidence-ranked fuzzy title matching second, with sequence-number and ambiguity guards. Completion reports provider files separately from matched, ambiguous, and unavailable catalog titles. Later refreshes reuse all persisted tier paths directly. The manifest contains filenames only, so scraping cannot unexpectedly start a catalog-sized download. Actual video remains lazy and downloads one region-preferred, Disc-1-first match when its game is opened. Artwork stays automatic and screenshots remain per-game/on-demand; this same media-type/console surface is the extension point for future catalogs and providers.

## Acceptance direction

The original 30 adversarial fixtures remain the hand-verified data-quality core inside the 100-game catalog. Expanded titles have explicit lightweight Libretro cover fallbacks and participate in runtime fuzzy media matching; broader exact-release coverage remains an ongoing data-quality gate.

## Release workflow

For GameStore, wrapping up an approved change means carrying it through the complete release path by default: merge the green PR, tag the version, wait for Windows and Linux release jobs, and verify the published installers plus updater metadata. Stop at a draft/release candidate only when Omid explicitly asks for review before release or a real acceptance gate prevents safe publication.
# Icon direction (2026-08-24)

- Packaged application source: `build/icon.png`; the full-resolution generation source is deliberate local scratch outside the shipped repository.
